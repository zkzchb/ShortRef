# 哈希协议：`sha256-base62-v1`

[English](hash-protocol.md) | 简体中文

这里明确规定 ID 生成协议，以便未来的其他实现能够复现相同的 ID。

## URL 规范化

哈希前执行以下处理：

1. 去除首尾空白字符。
2. 仅允许 `http` 或 `https`。
3. 将协议和主机名转换为小写。
4. 将国际化主机名转换为 IDNA ASCII。
5. 删除默认端口：HTTP 的 `80` 和 HTTPS 的 `443`。
6. 路径为空时使用 `/`。
7. 保留路径、查询字符串和 fragment。
8. 拒绝包含用户名或密码凭据的 URL。

不会删除跟踪参数。ShortRef 避免在未明确告知的情况下改变技术文档或平台 URL 的实际含义。

## 哈希与编码

1. 将规范化后的 URL 编码为 UTF-8。
2. 计算 SHA-256。
3. 将 32 字节摘要解释为一个无符号大端整数。
4. 使用 `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz` 进行编码。
5. 在左侧补 `0`，使 token 达到 43 个字符。
6. 初始 ID 使用前 8 个字符。
7. 发生碰撞时，依次尝试 9、10、11 和 12 个字符。

## 身份与迁移

哈希仅在首次创建时决定 ID。创建完成后，ID 即成为稳定的引用身份。更新目标地址时，不会重新计算或替换 ID。
